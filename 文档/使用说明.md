# 小软件 —— 机器人仿真桌面软件

> 双击图标就能打开的机器人仿真软件：3D 机械臂 + 可视化面板 + **可以随时自己写、自己换的控制算法**。
> 名字"驭臂" = 驾驭机械臂。名字里不含 "MuJoCo"（它是我们用的底层引擎，Apache-2.0，但其许可不授予商标权）。

---

## 一、第一次使用（换机器后只做一次）

```bash
cd ~/Desktop/驭臂
bash 工具/重建环境.sh
```

它会：① 用你机器上的 Python 造一个隔离环境 `.venv` → ② 装官方完整版 mujoco 3.13.0
（**优先用包内 `离线依赖/`，不需要联网**）→ ③ 修 macOS 上的 glfw 动态库。

> 为什么要单独造环境：conda 渠道的 mujoco 是"零件版"，**不含界面层和插件系统**
> （实测报错 `cannot import name 'sim' from 'mujoco.experimental.studio'`）。

## 二、日常使用

**双击桌面上的「小软件启动」图标**（或本文件夹里的 `小软件.app`）。

> **★ 第一次打开是"空白界面"**（只有一块地面，没有机械臂）—— 设计如此：不再强行塞给你 UR5e。
> 在右侧 **`Model library`【模型库】**面板里点一台即可（5 台可选，**点一下立刻切换，不用重启**）。
> **之后再启动会自动加载你上次用的那台。**

> **★ 点开任意模型，进去都是「静止在默认位置」**（2026-09-24 起的行为）：
> 不加载任何控制算法、不施加重力、物理冻结 —— 模型一动不动，方便你先看清姿态、再决定怎么动它。
> 想让它动，需要**你自己做两件事**（可以只做其中一件）：
>
> | 想干什么 | 怎么做 |
> |---|---|
> | 让它**受重力自然下落** | 勾上左上角【Display】的 **`Load gravity`（加载重力）** |
> | 让它**被控制算法驱动** | 在【Algorithms】页签勾选算法 → 按 **`Apply`** |
>
> 两个开关是**独立**的：只勾重力 → 它自己掉（没有算法托着就会一直掉）；
> 只 Apply 算法但没勾重力 → 物理冻着，什么也不会动。**两个都要**才会"算法控制着机械臂运动"。
>
> ★ **"我挂了算法，怎么一动不动？"—— 十有八九是物理还冻着。**
> 【Algorithms】面板顶部**直接显示物理状态**，并且**就地有按钮**：
>
> ```
> Physics FROZEN - the robot will NOT move   [run physics]
> ```
>
> 点 `run physics` 就等于勾上左上角的 `Load gravity`（同一条开关，会互相同步）。
> 物理开着时显示 `Physics running (gravity on)  [freeze]`。
>
> 另外：**`Apply` 按钮在"没有改动"时是灰的**（Apply 完就变灰），这是刻意的
> ——它表示"有个改动等着应用"。想换成别的算法，**改一下勾选**它就会重新亮。

窗口里除了官方自带的 19 个面板，还有 7 个我们自己的：

| 面板 | 做什么 |
|---|---|
| **Model library** | **选 / 切换机械臂**（5 台）；从本地导入模型；回到空场景 |
| **Algorithms** | ★ 选哪些控制算法挂在这台模型上（勾选 / 调序 / Apply 临时 / Save 写回）**列表最后一项说了算** |
| **Appearance** | **换面板外观风格**（5 套皮肤，见下）；也影响官方那 19 个面板 |
| **About** | 版本、运行时、已加载的插件清单、模型、合规声明 |
| **Monitor (metrics)** | 把插件 `指标()` 报上来的数画成实时曲线 |
| **Recorder** | 录制 / 回放，产出 CSV + 元信息（含 mujoco 版本与模型指纹） |
| **Controller params** | 拖滑杆**实时**改 KP/KD，不用改文件、不用重启 |
| **System identification** | 激励采样 → 后台辨识 → 看拟合改善多少倍 |

**这 7 个面板里，【模型库】是固定的**：它在窗口**左上角**、**没有 ×（关不掉）**、每次启动必定出现
—— 因为它是选机械臂的唯一入口（曾经被关掉过一次，结果每次都看不到，只能按 F9 找回）。
想挪位置直接拖，位置会记住。其余 6 个仍是浮动窗口，可以点 × 关掉、按 **F9** 全部找回。

> ★ **面板上的文字是英文**：官方 UI 字体没有中文字形（ImGui 会把中文画成一串 `?`），
> 所以按钮/标签用英文、状态用 `[ok]/[fail]`、列表用 `*`。**终端输出和本文档仍然是中文**。
> 想确认"面板上还会不会出现问号"：`./.venv/bin/python 优化（软件优化的报告都放这里面来）/验证/字体覆盖.py`。

### 【Display】左上角小方框：物理总闸

```
┌─ Display ─────────────────────┐   ← 常驻窗口左上角
│ ☐ Load gravity                 │   ← 勾上：施用重力，物理开始推进
│   frozen at the default pose   │
└────────────────────────────────┘
```

| 勾选框 | 效果 |
|---|---|
| **不勾（默认）** | **冻结在默认位置**：物理暂停，模型与仿真时间都不动 |
| **勾上** | **施用重力**：模型自然下落；有算法在控时被算法驱动 |

- 取消勾选时**先回到默认位置再冻结**（不会停在"掉到一半"的歪姿上）。
- 它**与算法列表无关**：清空算法后照样有效（是外壳的内置件，不依赖某个算法被加载）。
- 面板**没有 ×（关不掉）**：它是物理总闸，关掉会让模型悬空不动又找不到原因。

## 三、算法怎么挂到模型上（项目机制）

### 先理解"项目"

**一个项目 = 模型 + 算法列表 + 参数** 的一次命名快照，写在 `项目/*.json` 里：

```json
{
  "项目": "UR5e_基础PD",
  "模型": "模型/universal_robots_ur5e/ur5e_torque.xml",
  "算法": "*",
  "参数": { "关节 PD 位置控制": { "KP": 320.0, "KD": 42.0 } }
}
```

- `算法` 写 `"*"` = 用 `算法库/` 里的**全部**算法（加新算法后不用改项目文件）；
  只想挂几个就写成列表：`[{"插件": "关节pd控制"}, {"插件": "数据录制"}]`
- `参数` 由界面【Controller params】拖滑杆时**自动写回来** —— 下次打开这个项目就是你上次调好的值
- 一个模型可以对应多个项目（同一模型两组参数）
- 现有 5 个：`UR5e_基础PD` / `UR10e_基础PD` / `xArm7_基础PD` / `Panda_基础PD` / `iiwa14_基础PD`

### 点一个模型时发生了什么

```
你在【Model library】点 UR5e
   ↓
外壳按"哪个项目的 模型 字段指向它"反查 → 项目「UR5e_基础PD」
   ↓
读项目文件 → 解析 算法 字段 → 装配器按文件路径逐个 import（同名文件不会互相覆盖）
   ↓
兼容性预检：算法声明了 模型兼容性() 且与当前模型不匹配 → 不启用，并把原因显示出来
   ↓
换掉注册表里的用户算法 → 参数应用器重新绑定（否则滑杆会静默失效）
   ↓
通知各算法、按项目里存的参数回填 → 立刻发一条"项目状态"给界面
   ↓
界面上的 Project / Algorithms 两行马上更新，参数面板也换成这一组的参数
```

> 值得注意的两点：
> ① **算法实例是新建的**（`__init__` 会重跑），别指望实例状态跨模型保留；
>    该留的东西写进项目文件的 `参数`（滑杆会自动存），或实现 `模型已切换()` 钩子清缓存。
> ② **换模型时如果算法不兼容，是"不启用 + 说明原因"，不是"跑起来报错然后被永久停用"**。
>    例如 `末端两点运动` 声明了"需要 6 轴手臂"，所以在 Panda / iiwa14 / xArm7（7 轴）上会被跳过。

### 在界面上换算法（不用改文件、不用重启）

【工作台】→ **`Algorithms`** 页签：

```
Project: UR5e_基础PD  (saved in project file)
Library (6 available)          Selected (4) - last one wins
 [x] Joint PD position control   1. System identification
 [ ] Two-point task-space        2. Display pose
 [x] System identification       3. Recorder
 [ ] Sinusoid swing              4. Joint PD position control   <- controls the robot
 [x] Display pose                  [^] [v]
 [x] Recorder
[Apply (temporary)] [Save to project file] [Revert]
```

| 按钮 | 作用 |
|---|---|
| **Apply (temporary)** | 立刻按你勾的这组重新装配，**只对本次运行有效**（不动项目文件）—— 适合"我想试试正弦摆动单独跑什么样" |
| **Save to project file** | 把这组选择**写回** `项目/xxx.json`，下次打开还是它 |
| **Revert** | 丢掉未提交的勾选，回到当前真正在跑的那组 |

面板顶部会告诉你当前状态：
- `(saved in project file)` = 正在跑的这组就是项目文件里的
- `(temporary - not in project file)` = 是你在界面上临时改的
- `* unsaved edits` = 你勾了但还没 Apply/Save

> ★ **为什么必须能"上下调序"**：多个算法都写力矩时，**排在最后的那个最后写、它说了算**。
> 所以"选哪些"和"谁赢"是同一件事——想把某个算法换成主导，就把它调到列表最后。
> 面板上会标出哪一个是 `<- controls the robot`。
>
> ⚠️ 换个算法时**新装配的实例是全新的**（`__init__` 重跑），实例里攒的状态不会留；
> 但**参数会按项目文件恢复**（你调好的 KP/KD 不会丢）。
>
> ★ **为什么默认要勾上「Reset robot pose to home」**（这是踩过的真实困扰）：
> 多数控制算法的设计是"**拿第一次看到的位置当基准**"（关节 PD 的 `目标`、正弦摆动的 `基准`）。
> 而换算法时物理状态本来是不动的 —— 于是新算法会拿**上一个算法留下的姿态**当基准，
> 表现就是"试过几轮算法之后，机器人再也回不到默认位置了"。
> 实测：正弦摆动把机器人带到偏离默认位置 0.27 rad 的地方，切到关节 PD 后它就把**那个位置**
> 当成了起点。勾上这个框之后，每次切换都先回默认姿态，关节 PD 每次都稳定到**同一个**位置。
>
> 什么时候可以不勾：你想研究"**从当前姿态接着控制**"的行为（比如切换过程的瞬态）。
>
> ⚠️ 换个算法时**新装配的实例是全新的**（`__init__` 重跑），实例里攒的状态不会留；
> 但**参数会按项目文件恢复**（你调好的 KP/KD 不会丢）。

如果只想挂到某几个项目上，就在那些项目文件的 `算法` 列表里写上它：

```json
"算法": [{"插件": "关节pd控制"}, {"插件": "我的算法"}]
```

（`类` 字段可以省：模块里只有一个插件类时装配器自己认；有多个才需要写 `"类": "你的插件类名"`。）

一个算法的最小长相：

```python
import 插件系统 as 插件
from 插件系统 import 控制插件, 每步

class 我的插件(控制插件):
    名称 = "我的控制算法"
    版本 = "0.1"

    @每步                                        # 贴标签 = 参与每一步仿真
    def 每步控制(self, event: 插件.messages.StepEvent) -> bool:
        数据 = event.data
        数据.ctrl[:] = 数据.qfrc_bias             # ← 你的算法（这里只是重力补偿）
        return False

    def 可调参数(self) -> dict:                    # 可选：界面自动出现滑杆
        return {"KP": {"值": 100.0, "范围": (10.0, 2000.0)}}

    def 指标(self) -> dict:                        # 可选：界面自动出现曲线
        return {"误差": 0.0}
```

**三条硬规则**：
1. `@每步` 的方法**必须写类型标注**：`event: 插件.messages.StepEvent`（官方定的，不写会报错）
2. 文件名**不能以数字开头**（装配顺序由项目文件里的列表顺序决定）
3. **面板上只能显示 ASCII** —— 官方 UI 字体没有中文字形。`名称`/`说明` 可以用中文（只出现在终端），
   想在面板上显示的名字写 `英文名 = "..."`；`指标()` 的曲线名用中文前先在 `软件/界面文字.py` 登记英文。
   自检：`./.venv/bin/python "优化（软件优化的报告都放这里面来）/验证/字体覆盖.py"`

## 六、出问题怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击没反应 | 找不到包根或环境没建 | 看包根下的 `启动日志.txt`；先跑 `工具/重建环境.sh` |
| **双击提示"要安装 Rosetta"** | 老版 `.app` 用 bash 脚本当可执行文件，macOS 认不出这是原生 arm64 应用。**软件本身全是 arm64 原生，不需要 Rosetta** | 临时：终端跑 `./.venv/bin/python 软件/主程序.py`（不弹）。永久：重新打包 `./.venv/bin/python 工具/打包应用.py --包根 "$(pwd)" --名字 驭臂 --主程序 软件/主程序.py` |
| 弹窗"找不到安装位置" | 包文件夹被改名/移动了 | 把包放回桌面，或设环境变量 `小软件_包路径` 指向它 |
| `Failed to load GLFW3 shared library` | conda 的 glfw 找不到动态库 | `./.venv/bin/pip install --force-reinstall --no-deps glfw==2.10.2` |
| 某个面板不见了 | 面板加载失败（通常是方法缺类型标注） | 看 `启动日志.txt` 里的 ⚠ 行 |
| 官方升级后启动报接口自检失败 | 官方改了实验性 API | 按自检提示改，或退回实测版本：`./.venv/bin/pip install -r requirements.lock` |
| **面板里出现一串问号 `?????`** | 官方 UI 字体（Atkinson Hyperlegible）没有中文字形，ImGui 缺字形就回退画 `?`。**不是故障，也不是编码坏了** | 已全面改成 ASCII（面板按钮/标签用英文，中文留给终端）。若还有，跑 `./.venv/bin/python 优化（软件优化的报告都放这里面来）/验证/字体覆盖.py` 看是哪一行；插件里可以加 `英文名 = "..."` |
| **皮肤没生效 / 只有部分面板变了** | 官方改了 `ux.setup_theme`（皮肤靠"包装它"来覆盖那 19 个官方面板） | 看 `启动日志.txt` 里的 ⚠ 皮肤 行；皮肤会自动退回"只换自研面板"，不会崩。也可按 F10 或 `--风格 关` 先回到官方外观 |
| 想清掉记住的外观风格 | 风格存在 `输出/外观.json` | 删掉它（下次用默认「现代深色」），或 `--风格 关` |
