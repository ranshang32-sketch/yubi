> 调研方法：仅采用官方文档 / 官方仓库 / 官方 PyPI 页面。凡官方未明确写出的条目，一律标「未查证」，不做推测。

## 软件名：MuJoCo（Google DeepMind，3.13.0，2026-09-08）

- **一句话定位**：通用关节坐标物理引擎（C/C++ 库 + C API），面向机器人、生物力学、图形/动画与机器学习，主打「单步低延迟 + 软接触凸优化模型 + 解析可逆动力学」，是当前强化学习事实标准仿真器之一。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>、<https://pypi.org/project/mujoco/>
- **许可证 / 闭源商用**：Apache License 2.0（PyPI 页面明确写明 "MuJoCo and its Python bindings are licensed under the Apache License, Version 2.0"；官方 Overview 称 2021 年 10 月由 Google DeepMind 收购并 freely available、2022 年 5 月开源）。Apache-2.0 属宽松许可、无 copyleft 传染；**官方文档未逐字写「可闭源商用」**，需法务按 Apache-2.0 条款自行确认（该许可证本身允许闭源分发与商用）。
  来源：<https://pypi.org/project/mujoco/>、<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>
- **支持平台（含 macOS）**：官方编程指南写明「Windows、Linux 和 macOS，需要支持 AVX 指令的处理器」，并提供 **x86_64 与 arm64** 预编译动态库；macOS 提供 `.dmg`，内含 `MuJoCo.app`（双击即启动 `simulate` GUI），可拖入 `/Applications`，DMG 还含 `mujoco.framework` 与公开头文件（可直接用于 Xcode/Swift）。**⇒ macOS + Apple Silicon（M 系列）是官方一等支持平台。**
  另注：changelog 3.13.0 增加 Python 3.15（含 free-threading）支持；3.3.1 修过 macOS 上 `ARB_clip_control` 缺失导致的阴影闪烁。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/programming/index.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- **A 物理引擎**：
  - 自研 C 引擎，广义坐标（joint coordinates）+ 现代接触动力学（凸优化形式，**非 LCP**），接触/约束为「软约束」，参考加速度由 `solref`（timeconst+dampratio 或 -stiffness/-damping 直写）与 `solimp`（5 参数阻抗曲线）参数化；官方明确「接触模型软约束使系统辨识接触参数成为可能」。
  - 求解器：**Newton（默认）**、CG（Hager-Zhang 非线性共轭梯度 + 精确线搜索）、PGS；另有 NoSlip 后处理（`noslip_iterations`）用于压制软接触固有滑移。默认 `iterations="100"`、`tolerance` 1e-8（testspeed 默认值）。
  - 摩擦锥：`pyramidal`（默认）/ `elliptic`；Jacobian：dense/sparse/auto（auto 在 nv≤60 用 dense，>60 用 sparse）。
  - 碰撞：3.2.3 引入、3.3.0 起默认的 **native convex collision detection（nativeccd）**，可选 `multiccd` 支持任意大网格；box-box 另有专用图元 collider。
  - **约束岛（islands）**：自动发现互不耦合的约束子图并分块求解，支持逐岛并行、跳过无约束自由度；3.4.0 引入**休眠（sleeping islands）**，可冻结静止岛。
  - **CPU 并行**：官方明确「单次仿真步默认单线程；岛内可并行；大规模数据并行通过多份共享同一 `mjModel` 的 `mjData` 跑在不同线程」。`mujoco.rollout` 提供原生多线程 rollout（传 `nthread` 份 `MjData` 自动建线程池）；`testspeed --nthread` / `--nenginethread` 分别对应「多轨迹并行」与「引擎内部线程池」。
  - **GPU 并行**：两条官方后端——**MJX**（JAX，见下）与 **MuJoCo Warp（MJWarp，见下）**；两者消费同一 `mjModel`/`mjData`，可与 CPU 无缝互转。
  - 可变形体：3.0 起 `flex`（1D capsule/2D 三角/3D 四面体，支持碰撞与接触力），`flexcomp` 自动化生成；**trilinear（3.3.0）**与 **quadratic（3.4.0）** 快速可变形体（仅 8/27 个角点自由度）；3.5.0 为 flex 增加 `implicit`/`implicitfast` 隐式积分；分离碰撞网格与形变网格以固定软体计算成本。
  - 流体：官方明说「完整流体动力学超出 MuJoCo 范围」，只提供两种**静态（无附加状态）唯象模型**：惯性模型（基于等效惯性盒）与椭球模型（每 geom 5 个可调系数，含附加质量、钝体/细长体阻力、角阻力、Magnus 与 Kutta 升力、粘性阻力），适用于飞行/游动。
  - 其他 actuator 模型：SISO 与 MIMO 并存（3.11.0 重构引入 `ctrlnum`/`outnum`）；3.12.0 新增 **PID actuator** 与重新设计的 **dcmotor**（支持 back-EMF、cogging、friction 作为被动关节力）；支持 activation 状态（integrator/filter/filterexact/muscle/user）；传动类型含 joint、tendon、jointinparent、slider-crank、site、body（真空吸盘/黏附）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/computation/index.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/computation/fluid.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/programming/samples.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- **B 传感器**：官方概述列出 touch 传感器、**IMU**、力/力矩传感器、关节与肌腱位置/速度、actuator 传感器、body frame 传感器、**rangefinder** 等，并明确「另有 user sensor 类型供插入任意量」。
  - **相机类（RGB/深度）不是内建 sensor 类型**：官方原文「MuJoCo also has off-screen rendering capabilities, making it straightforward to simulate both color and depth camera sensors. This is not included in the standard sensor model and instead has to be done programmatically」。
  - **噪声/真实感建模**：sensor 的 `noise` 属性官方定义是「该传感器噪声模型的标准差；**该属性不影响仿真**，只是为后续使用提供存放位置」，即 MuJoCo 本身不做噪声注入。另有 `cutoff`（输出绝对值限幅）、`nsample`（时间索引环形缓冲）、`delay`（从历史缓冲按 `time-delay` 读数）、`interval`（`period phase`，可按大于 dt 的周期重算传感器）、`interp`（zoh/linear/cubic）：3.5.0 起 actuator 与 sensor 均支持任意延迟与采样间隔，延迟写在小数级别时可用于 system identification 与随机延迟建模。**⇒ 噪声/延迟仿真机制齐全，但噪声本身需用户实现。**
  - 相机模型：支持 perspective / orthographic，内参 `fovy`、`ipd`（立体）、以及标定用的 `focal`（横纵焦距不同）与 `principal`（主点偏心），配 `sensorsize` + `resolution` 可画出视锥。
  - 触觉：3.5.0 新增 `tactile` sensor（给定点处穿透深度 + 切向滑动速度，仅在与 SDF 碰撞时报告）；`contact` sensor（按用户条件输出定长接触信息）；3.13.0 为 tactile 增加 `cutoff`。
  - **无内建 LiDAR**：官方 sensor 列表无 lidar/ray-cast 阵列传感器类型；仅 rangefinder（可挂到相机上按 `resolution` 逐像素投多射线，见 3.5.0）与 ray-cast API。**LiDAR 传感器未查证有官方实现。**
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/modeling.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- **C 建模**：
  - 原生格式 **MJCF**（XML，含 CSS 式 `default` 类继承机制）；官方支持加载 **URDF**（含 `<mujoco>` 扩展段，可插 `compiler`/`option`/`size`，并说明 URDF 不做 schema 校验、属性拼错会被静默忽略）、**MJZ** zip 归档、**OpenUSD**（3.5.0 起 OpenUSD 解析从 experimental 移入 `mjpDecoder` 插件，可构建/导入/导出）。
  - 网格资产：**OBJ**（三角网格）与二进制 **STL**；纹理 PNG / KTX（3.12.0 起不再支持自定义二进制纹理格式）；高度场 PNG 或自定义二进制；网格可就地嵌入 XML；碰撞用凸包。
  - **CAD 导入（STEP/IGES）：未查证有官方支持**。官方仅建议「用 MeshLab 等软件从其他格式转换」。
  - 关节/传动/执行器：见 A 节（armature、damping、frictionloss、springref、stiffness 等关节属性齐备；传动含 gear、pulley、slider-crank）。**减速器/齿轮箱建模**：官方提供 `gear` 传动比与 tendon/pulley 耦合，但**未见官方专门的减速器（harmonic drive 非线性、齿隙）模型**——`solimp` 位置相关阻抗可用于「近似 backlash」，官方在 solimp 文档中如此表述。**专用减速器模型：未查证。**
  - 摩擦：`geom/friction`（滑动/扭转/滚动三方向）、`joint/frictionloss`（干摩擦）、`tendon` 摩擦损失、`pair/friction`；3.11.0 新增 `geom/adhesion`、`pair/adhesion`（可做「远距离黏附」即磁铁）、`geom/surfacevel`（传送带/跑步机/转盘）。
  - 软体建模：`flex` + `flexcomp` + `skin`（仅可视化的蒙皮变形），支持从网格（含四面体网格）生成，官方推荐 fTetWild 做表面→四面体转换。
  - 传感器/执行器延迟：3.5.0 起支持任意延迟（history buffer），并新增 `mjData.history` 状态变量。
  - 程序化建模：`mjSpec`（C）与 Python `MjSpec`（3.2.5 起 stable），支持 add/delete body/geom/joint、attach 子模型、序列化到 XML/MJB/MJZ、`to_zip`。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/modeling.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/python.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- **D 算法生态**：
  - **ROS / ROS2 桥接：官方 MuJoCo 文档中未查证**（readthedocs 目录无 ROS 章节；社区有第三方 `mujoco_ros2` 等，但非官方，本清单不计）。
  - **MoveIt / 运动规划：未查证官方集成**。MuJoCo 自身提供逆运动学/逆动力学原语与 `mujoco.minimize`（非线性最小二乘，`mju_boxQP`）、`mjd_transitionFD`（有限差分动力学导数），可作为规划/优化底层。
  - **强化学习**：官方 Overview 明确支持「parallel sampling for machine learning」，`rollout` 模块做多线程轨迹展开；GPU 侧官方有 **MuJoCo Playground**（Apache-2.0，`pip install playground`，含 dm_control 经典控制、四足/双足运动、非抓取与灵巧操作、视觉环境，支持 MJX-JAX 与 Warp 两种实现，CLI `train-jax-ppo --impl warp`）；**mjlab**（Apache-2.0，复用 Isaac Lab 的 manager-based API，底座为 MuJoCo Warp + PyTorch，含 RayCast 与 RGB-D 相机 sensor 文档）；dm_control（DeepMind 官方 RL 库，依赖 `mujoco` 包并被继续支持）；Brax 依赖 `mujoco-mjx`（Brax 旧 generalized pipeline 已不再维护）。**Gym / Gymnasium API：MuJoCo 本体不提供，由 dm_control / Playground / 第三方提供（未查证 MuJoCo 官方 Gym 封装）。**
  - **模仿学习**：官方文档未查证专门模块；mjlab 文档有 Motion Imitation 章节。
  - **参数辨识 sysid**：**官方有专用工具箱**——3.5.0 起「Added a new **System Identification** toolbox (Python)」，位于仓库 `python/mujoco/sysid/`，有 README 与 Colab notebook，贡献者含 @kevinzakka、@qiaoyuanl 等；配套 `mujoco.minimize.least_squares()`（SQP + `mju_boxQP`）与 `least_squares.ipynb`；官方建议用 `solref` 的「直写 stiffness/damping」格式做系统辨识；延迟/随机延迟建模也是为 sysid 服务。**sysid 的完整 API 列表：官方未在 readthedocs 成章文档化（只有 README + notebook），本次未能读取 README 正文（GitHub 直连被环境屏蔽）→ 细粒度 API 标未查证。**
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.html>（3.5.0 条目）、<https://mujoco.readthedocs.io/en/stable/_sources/python.rst.txt>、<https://pypi.org/project/playground/>、<https://mujocolab.github.io/mjlab/main/index.html>
- **E 仿真能力**：
  - 大规模并行：CPU 用 `rollout` + 多线程；GPU 用 MJX（`jax.vmap`/`jax.pmap`，可多设备）或 MJWarp（`nworld` 世界数、`nconmax`/`naconmax`/`njmax` 固定缓冲、CUDA graph 捕获、compact solver、稀疏 Jacobian 省显存）。官方 MJWarp 文档给测试环境 aloha_clutter（nv=136、2048 worlds、njmax=384）等 nightly benchmark；MJX 文档给「单 humanoid：MuJoCo CPU(Apple M3 Max 64 线程) 650K SPS、AMD 3995WX 1.8M SPS、A100 batch 8192 950K SPS、TPU v5e-8 batch 16384 2.7M SPS」以及 MJX-Warp 的 Humanoid 3.35M SPS。**「最多多少环境」官方不设上限，取决于显存与 nconmax/njmax。**
  - 领域随机化：MJX 中 `mjx.Model` 支持 batch 维（官方明确「Batch dimensions are a natural way to express domain randomization (in the case of mjx.Model)」）；MJWarp 支持 per-field batch（`batch_sizes={"dof_damping": 2}`）与 per-world 资产（逐世界 mesh/hfield/material/texture 替换）；3.11.0 新增 `body/simple="auto"` 用于「模型参数在编译后仍会变化」的 domain randomization 场景。
  - **时间倒带 / 回放**：官方 viewer/simulate 支持 **Left arrow 通过 history buffer 单步后退**（shortcuts 表明确列出），并有 `sim_history`（Studio 的 C++ 头文件里含 `sim/sim_history.h`）与 `mj_copyState` / `mj_extractState`（3.4.0）便于状态快照/回放；Studio 有 `SimulationTimelineState timeline_`。**通用「任意时刻倒带」的公开 API 未查证。**
  - 录制与数据导出格式：`record` 样例输出**原始 RGB(D) 数据文件**，官方示例用 **ffmpeg** 转 mp4（非内置视频编码）；`render` 样例直接输出 **PNG**（支持 Filament(PBR) 与 classic 两种后端、headless）；截图 `Ctrl P`；模型导出 **MJCF/MJB/MJZ/TXT**、数据 `mj_printData` 输出 **MJDATA.TXT**、模型 `Ctrl M` 输出 **MJMODEL.TXT**；Python 侧 `mujoco.usd.exporter.USDExporter` 导出 **USD/USDA/USDC** 场景与轨迹（安装 `pip install mujoco[usd]`）。
  - **可复现性（固定随机种子）**：官方 python 迁移文档写明「MuJoCo library's computation is deterministic given a specific input」。但 **MJWarp 官方明确「Is MJWarp on GPU deterministic? No.」**（GPU 原子操作带来顺序与小数值差异），官方给出的确定性方案是 `wp.set_device("cpu")`；MJX/MuJoCo Playground FAQ 提示 NVIDIA Ampere 及以后 GPU 上 JAX 默认 TF32 会影响复现性，需 `export JAX_DEFAULT_MATMUL_PRECISION=highest`。MuJoCo 自身**未提供全局随机种子 API**（无内建随机源，用户代码自管）——官方文档未查证有 seed 概念。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/programming/samples.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/python.rst.txt>、<https://pypi.org/project/playground/>
- **F 界面与交互**：
  - 三套 GUI：①C 版 `simulate`（原生 OpenGL，含 help/info/profiler/sensor 曲线、拖拽加载模型、可视化分组、相机与渲染开关、F1 帮助）；②Python `mujoco.viewer`（基于同一 Simulate UI）：managed（`viewer.launch`，阻塞）、standalone（`python -m mujoco.viewer --mjcf=...`）、passive（`viewer.launch_passive`，非阻塞，返回 handle 提供 `cam`/`opt`/`pert`/`lock()`/`sync(state_only)`/`user_scn` 等）；③**MuJoCo Studio**（实验性，见专节）。
  - **拖拽交互**：官方明确支持「reach into the simulation, push objects around」；支持拖拽加载模型文件；`simulate` 中左键双击选中物体后 Ctrl+拖拽施加力/力矩、Ctrl 拖拽旋转、Ctrl+右键拖拽平移、Ctrl+右双击跟踪 body；Python 端 `mjv_movePerturb` / `mjv_applyPerturbForce` / `mjvPerturb` 为抽象鼠标钩子（可自定义）。
  - **中文界面：未查证**。官方 UI 文档说主题/外观「不提供逐个元素定制」，元素类型为 checkbox/radio/list/slider/textbox/static text/button/separator，**未提及任何多语言或 i18n 机制**。
  - 脚本语言：官方绑定为 **C/C++ API + Python（pybind11）**；另有 Unity 插件、OpenUSD 插件。
  - **图形化编辑器（在线改模型结构）**：官方 `simulate`/viewer **不是模型结构编辑器**（可改物理/渲染选项、控制量、相机，模型结构改动需改 XML 后 Ctrl L 重载）；**MuJoCo Studio 有 Spec Explorer / Spec Editor 面板**（源码里 `SpecExplorerGui()`、`SpecEditorGui()`、`spec_editor.h`，且 UI 状态含 `SpecPropertiesMode {kSpec, kModel, kData}`），属于实验性。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/programming/ui.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/python.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/programming/samples.rst.txt>、<https://cdn.jsdelivr.net/gh/google-deepmind/mujoco@main/src/experimental/studio/app.h>
- **G 可视化**：
  - **两套官方渲染器**：Classic（OpenGL 1.5 fixed-function + 预上传 GPU 资源）与 **Filament**（Google 的实时 PBR 引擎，跨 Linux/Windows/macOS/Android/iOS/Web，支持 OpenGL/Vulkan/Metal；构建时设 `MUJOCO_USE_FILAMENT=1` 替换 `mjr` 实现并暴露 `mjrf_*` API）。**路径追踪（path tracing）：未查证**（Filament 为实时 PBR，非离线路径追踪；官方未声明 path tracer）。
  - 效果开关：`mjvScene.flags`（`mjtRndFlag`）含 wireframe、**shadow**、**reflection**、skybox、fog、haze、depth、id color、cull face 等；3.12.0 增加 `light/softness`（聚光灯边缘软化）；3.13.0 修 PBR metallic 回退色（黑→白）。
  - **深度图 / 分割图导出**：**MuJoCo C 渲染器不提供语义分割**；深度图可通过 offscreen `mjr_readPixels` + `record` 样例（`adddepth` 参数）导出。**真正带分割的是 MJX / MJWarp 的批量渲染器**：`mjx.render_with_segmentation` 返回 `(rgb, depth, seg, d)`，`mjx.render` 返回 `(rgb, depth, d)`（3.12.0 起把 `mjx.Data` 追加为返回值最后一项）；MJWarp 的 `create_render_context` 支持 `render_rgb`/`render_depth`、逐相机分辨率/内参、纹理、阴影、mesh/hfield/flex 渲染、**3D Gaussian Splatting（含物理遮挡）**，官方说明它是「single hit raycaster optimized for high throughput and low fidelity」，**不支持全局光照、PBR 材质、view-dependent SH**。**语义分割目前只在 MJX-JAX 路径（`render_with_segmentation`）有官方 API。**
  - 视频导出：无内置编码器，`record` 出 raw RGB 后交给 ffmpeg；MJWarp `mjwarp-render` 可 `--output_video=orbit.gif` 生成相机环绕 GIF；3.13.0 新增 `render` 样例输出 PNG。
  - 多视口：`mjvScene` 内嵌两个 `mjvGLCamera`（双眼），支持立体（quad-buffered / side-by-side）；MuJoCo 提供 window 与 offscreen 两个 FBO；**同窗口多视口 mosaic 未查证**（Studio 有 picture-in-picture 面板 `pips`，但属实验性）。
  - 可视化辅助：接触点/接触力（法向+切向）、等效惯性盒、凸包、骨架、约束违反、空间坐标系、文本标签、肌腱、岛（Island）、Body/Mesh tree 等。

- **I 精度实时性**：
  - 默认 `timestep="0.002"`（2 ms，官方选项参考原文），并称其为「speed-accuracy trade-off 中最重要的单一参数」，实时要求「timestep 大于每步 CPU 时间（RK4 需 4 倍）」。
  - 默认积分器 `Euler`（半隐式），可选 `RK4`、`implicit`、`implicitfast`、**`discrete`（3.13.0 新增，离散速度步，把约束求解与隐式位置/速度更新统一在有效惯性度量 M̂ = M + hD + h²K 中，使被动弹簧与位置伺服在远超显式稳定极限的步长下稳定）**。
  - 定频闭环：官方未提供框架级 fixed-frequency 控制环 API，但模型可带 `keyframe`，且 `simulate`/viewer 有加速减速（`+`/`-`）与 pause/step；大量工程实践以 Python 循环按 `timestep` 节拍 `time.sleep`（Python 文档的示例即如此，并注明示例「does not necessarily keep the physics ticking at the correct wallclock rate」）。
  - **实时倍数（RTF）**：官方 `testspeed` / `mjx-testspeed` / `mjwarp-testspeed` 可测 SPS 与 realtime factor；MJX 文档给出明确对照数据（见 E 节），并明确 MJWarp 优化吞吐（总步/秒）而 MuJoCo 优化延迟（单步时间），**同一个仿真步 MJWarp 预期比 MuJoCo 慢**，故 MuJoCo 更适合实时/在线控制（MPC）与交互式图形界面（遥操作）。
  - **CPU 单线程性能**：官方声明「运行期零内存分配」（`mjData` 预分配）、单步默认单线程；MJX 文档明确「单场景（1 份 mjData）在 MJX-JAX 上可能比 MuJoCo **慢 10 倍**，MuJoCo 针对 CPU 精心优化过」——即 MuJoCo CPU 单线程是刻意优化的强项。
  - 数值可复现：CPU 端确定性（官方表述「deterministic given a specific input」）；GPU 端 MJWarp 非确定性（原子操作），需 CPU 设备求确定性；MJX-JAX 有 TF32 复现性注意事项。官方另有 `fwdinv` 标志可在每步后自动比较正/逆动力学并把差异写入 `mjData.solver_fwdinv`（求解器收敛自检）。

  1. **macOS（含 Apple Silicon）一等公民 + 极低部署摩擦**：官方 arm64 预编译库、`MuJoCo.app` DMG、`pip install mujoco` 一条命令即得引擎与 viewer，且 MJX-JAX 官方支持 Apple Silicon 跑 GPU 批仿真。对 M5 + macOS 的自研软件，这是唯一「零门槛且官方支持」的对照组。
  2. **单步低延迟 + 解析可逆动力学 + 软凸接触模型**：官方自称 optimized for latency，MJX 文档实测单场景比 MJX-JAX 快约 10 倍；接触模型有「唯一确定的逆动力学」（这是能做 sysid、MPC、可微优化闭环的根基）。
  3. **官方参数辨识（sysid）工具箱 + 延迟/采样率建模**：3.5.0 起把 sysid 做成官方 Python 工具箱（含 notebook），并把 actuator/sensor 的任意延迟、非整数采样周期、zoh/linear/cubic 插值做成引擎级特性——这是「仿真-真机对齐」这一环少见的官方级投入。

  2. **不是一体化创作工具**：无官方模型结构 GUI 编辑器（Studio 仍是 experimental）、无中文界面/i18n、无内置视频编码、无官方 ROS2 / MoveIt 集成章节、通用时间倒带只有 viewer 的 history buffer。
  3. **GPU 端牺牲确定性与实时性**：MJWarp 官方明确 GPU 非确定性、单步比 CPU 慢，且不支持自动微分（PGS/noslip/PLUGIN sensor 也未支持）；MJX-JAX 可微但接触/大网格性能弱（网格建议 ≤200 顶点、凸-凸 <32 顶点，单场景比 CPU 慢约 10 倍）。而 MuJoCo 本体单步默认单线程、CPU 大规模并行要靠 `rollout` 多线程。

## 软件名：MuJoCo Warp（MJWarp，3.13.0，2026-09-09 上 PyPI；3.5.0 起官方正式发布）

- **一句话定位**：MuJoCo 的 Warp（NVIDIA）实现，专为 **NVIDIA GPU** 优化的大批量并行仿真后端，由 Google DeepMind 与 NVIDIA 联合维护，是 **Newton** 项目的一部分；与 MJX 共享同一 API 形态，可作 MuJoCo 的 drop-in 替代（吞吐场景）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://pypi.org/project/mujoco-warp/>
- **许可证 / 闭源商用**：Apache-2.0（PyPI License expression: Apache-2.0；README 明写 "MJWarp is released under the Apache 2.0 license"）。PyPI Development Status 标为 **3 - Alpha**。
- **支持平台（含 macOS）**：**面向 NVIDIA GPU**；官方明确「MuJoCo Warp requires an NVIDIA GPU for fast simulation but supports CPU for development and debugging」（`wp.set_device("cpu")`）。**⇒ macOS + Apple M5 上只能走 CPU 路径做开发/调试，无法获得 GPU 加速**；Mac 上做 GPU 并行应改走 MJX-JAX（官方支持 Apple Silicon）。Wheel 标签 `py3-none-any`。
  来源：<https://pypi.org/project/mujoco-warp/>、<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>
- **A 物理引擎**：MuJoCo 引擎在 Warp 中的重实现；**与 MuJoCo 的差异官方清单**：不支持 `IMPLICITFAST` 的 midpoint integrator 特性、**不支持 PGS 与 noslip 求解器**、不支持 `PLUGIN` 类型 actuator/sensor、**Flex 为实验性（未全部实现或优化）**、`o_margin`/`o_solref`/`o_solimp`/`o_friction` 接触 override 不可用、`DISABLE`/`ENABLE` 若干标志缺失；MJWarp 独有选项含 broadphase/broadphase_filter/graph_conditional/contact_sensor_maxmatch/warn_overflow。批量维度参数：`nworld`（世界数）、`nconmax`/`naconmax`（接触数上限）、`njmax`（每世界约束上限）、`nccdmax`/`naccdmax`、`nvmax`（compact solver 的活动自由度上限）。**Compact solver**：配合 sleeping islands，把每世界的活动 DoF 压缩到定长 `nvmax` 工作区，用 GPU tile 运算做分块 Cholesky（官方示例 `make_data(nworld=2048, nvmax=64)`）；对单棵大运动链的扩展性不如 MuJoCo（官方称 >~60 DoF 的单连通机构仍是活跃优化项）。官方还说明 MJWarp **用 float32**（MuJoCo 默认 double），故数值结果与 MuJoCo 不同。
  来源：<https://pypi.org/project/mujoco-warp/>、<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>
- **B 传感器**：与 MuJoCo 同源（`PLUGIN` 类型 sensor 除外）；**自带 GPU 批量渲染器**（渲染能力见 G 节）。**接触传感器特殊语义**：即使某 geom 对未发生碰撞，只要它参与任何 collision sensor 的匹配条件，也会报告 1 个 contact（与 MuJoCo/MJX 不同，MJWarp 在主碰撞管线里顺带算 sensor 数据）；有 `contact_sensor_maxmatch` 上限，超出部分被忽略。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>
- **C 建模**：与 MuJoCo 相同的 `mjModel`/`mjSpec`/MJCF；支持**逐世界资产异构**（per-world meshes/hfields/materials/textures）；逐字段 batch（`batch_sizes`）；模型字段改动推荐「改 `mjSpec` 再 compile」，但 compile 需 host call（nworld 个实例即 nworld 次 host call），少数字段可 on-device 直接改（有 GitHub issue 跟踪扩展）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>
- **D 算法生态**：官方给出 RL 训练路径——**Isaac Lab 经 Newton API 集成 MJWarp**（`feature/newton` 分支）、**mjlab**（Apache-2.0，Isaac Lab 风格 manager API + MJWarp + PyTorch）、**MuJoCo Playground**（经 MJX API，`--impl warp`）。与 **JAX**（经 Warp 互操作，MJX 提供 `impl='warp'`）与 **PyTorch** 均可互操作。物理回调以 Python 函数挂在 `Model.callback` 上（control/passive/act_dyn/act_gain/act_bias/sensor/contactfilter），与 MuJoCo 全局函数指针机制不同。SDF 插件可用 Warp kernel 实现。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://pypi.org/project/mujoco-warp/>
- **E 仿真能力**：吞吐优先（官方：MJWarp 优化总步/秒，MuJoCo 优化单步延迟，**同一步 MJWarp 预期更慢**）；CUDA graph 捕获显著提速（文档推荐 `wp.ScopedCapture`）；多 GPU 可用 `wp.ScopedDevice`（每设备一张图）；官方 nightly benchmark 公开；**确定性：GPU 上「No」**（原子操作 → 顺序/微小数值差异），要确定性需 `wp.set_device("cpu")`（有 issue #562 跟踪）；溢出（contact/constraint/CCD/nvmax 缓冲）需用户监控 `Data.overflow` 与 `warn_overflow`（GPU printf 会严重拖慢，建议关闭并在 rollout 边界检查）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>
- **F 界面与交互**：命令行 `mjwarp-viewer <scene.xml>` 交互式查看；`mjwarp-testspeed`（含 `--measure_alloc`、`--memory`、`--event_trace`、`--nvmax`）；`mjwarp-render`（支持 3DGS PLY、`--orbit` 生成环绕 GIF）。**独立完整 GUI 编辑器：未查证**（官方仅文档化 CLI 工具）。

- **G 可视化**：**高吞吐 GPU 批量渲染器**——官方定位「single hit raycaster optimized for high throughput and low fidelity」，面向「多相机 × 多并行世界」；支持 mesh、纹理、heightfield、flex 形变体、**3D Gaussian Splatting（带物理遮挡）**、异构多相机（各自分辨率/FOV/内参）、光照与阴影；官方明确**不支持**：全局光照等高级光照、PBR 材质属性、3DGS 的高阶球谐（SH>0）。输出缓冲按 `(nworld, npixel)` 堆叠，`get_rgb`/`get_depth` 取出；另有 `render_with_segmentation` 出现在 MJX 侧（见 MJX 节）。渲染吞吐随分辨率与相机数线性缩放。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://pypi.org/project/mujoco-warp/>
- **H 部署**：`pip install mujoco-warp`（Apache-2.0，Python ≥3.10）；需 NVIDIA GPU（CUDA）获得性能，CPU 可跑但仅用于开发/调试。**macOS 上无官方 GPU 支持说明**。headless 天然适合（批量渲染器无窗口）。多 GPU 支持。
- **I 精度实时性**：**float32**（vs MuJoCo double），官方提示摩擦等对浮点精度敏感的参数可能导致与 MuJoCo 结果不同（甚至 NaN，建议开 issue）；solver `tolerance` 被 clamp 到最小 1e-6；一旦所有 world 收敛可提前退出（故 `iterations`/`ls_iterations` 对性能影响比 MJX 小）；MJX-Warp 官方给 SPS 示例：Humanoid 3.35M SPS（pure Warp）、2.96M（JAX FFI）、Aloha Pot 2.45M/2.33M。**不同积分器/求解器支持见 A 节。**
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>
- **J 生态**：与 MJX/Playground/mjlab/Isaac Lab(Newton) 组成生态；`mjlab` 文档含 RayCast sensor 与 RGB-D camera 章节（在 MJWarp 之上补齐感知 sensor 抽象）；nightly benchmark 公开站点 `google-deepmind.github.io/mujoco_warp/nightly/`；PyPI 状态 Alpha，月度跟随 MuJoCo 版本发版。
  来源：<https://pypi.org/project/mujoco-warp/>、<https://mujocolab.github.io/mjlab/main/index.html>
- **这个软件独有 / 明显强于别人的 3 项**：
  1. **在「复杂场景 × 数千并行世界」上的 GPU 吞吐**：官方明确「scales better than MJX on nearly every workload, in particular complex simulation scenes」，并给出 2048 worlds / nv=136 / njmax=384 这类实际配置与 nightly benchmark。
  2. **sleeping islands + compact solver**：把静止体休眠并把活动 DoF 压成定长 tile，是 GPU 上处理「大量 DoF 但每世界只有少数活动」的关键工程，其他 GPU 仿真器少见等价设计。
  3. **高吞吐批量渲染（多相机 × 多世界）+ 3DGS 物理遮挡**：百万帧/秒量级的 raycast 批量渲染，并支持高斯泼溅与真实几何互遮挡，直接服务视觉 RL / sim-to-real。
- **已知短板 2~3 项**：
  1. **不支持自动微分**（官方明确「MJWarp is not currently differentiable」，issue #500 跟踪）；PGS / noslip / PLUGIN sensor 也不支持，Flex 实验性。
  2. **GPU 非确定性 + float32**：官方 FAQ 明确 GPU 不确定、数值与 MuJoCo 不同；确定性只能退回 CPU，等于放弃加速。
  3. **对我们最致命：Mac 上无 GPU 收益**。官方仅支持 NVIDIA GPU，M5/macOS 只能 CPU 跑（且 CPU 路径本就不是它的目标场景）。

## 软件名：MJX（MuJoCo XLA，3.13.0，2026-09-09 上 PyPI；`mujoco-mjx` 包）

- **一句话定位**：MuJoCo 的 **JAX/XLA 实现**，用 `jax.vmap`/`jax.pmap` 在 CPU/GPU/TPU（含 **Apple Silicon**）上做批量并行仿真；同一包内提供两条实现：**MJX-JAX**（可微，小场景好）与 **MJX-Warp**（性能更好，不可微）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>、<https://pypi.org/project/mujoco-mjx/>
- **许可证 / 闭源商用**：Apache-2.0（PyPI License expression: Apache-2.0；页面原文「MuJoCo and its libraries are licensed under the Apache License, Version 2.0」）。Development Status: 5 - Production/Stable。
- **支持平台（含 macOS）**：官方明确 MJX-JAX「**runs on: Nvidia and AMD GPUs, Apple Silicon, and Google Cloud TPUs**」。**⇒ 这是我们 M5 + macOS 上唯一能拿到「官方支持的 GPU 批量仿真」路径。** MJX-Warp 走 NVIDIA GPU。Python ≥3.10，wheel 纯 `py3-none-any`。
- **A 物理引擎**：与 MuJoCo 同一套算法（MJX-JAX）/同一 Warp 实现（MJX-Warp）。**特性对照表（官方）关键差异**：
  - 可微：MJX-JAX ✓（"mostly supported"，issue #2259）；MJX-Warp ✗。
  - Joint：MJX-JAX 仅 FREE/BALL/SLIDE/HINGE；MJX-Warp 全部。
  - Geom：MJX-JAX 完全实现 PLANE/HFIELD/SPHERE/CAPSULE/BOX/MESH；ELLIPSOID/CYLINDER 实现但只与图元碰撞；BOX 按 mesh 实现；SDF 不支持。MJX-Warp：全部。
  - Constraint/Equality/Tendon/Tendon wrapping：MJX-Warp 全支持；MJX-JAX 为子集。
  - Integrator：MJX-Warp 除 `IMPLICITFAST` midpoint 特性外全支持；MJX-JAX 支持 EULER/RK4/IMPLICITFAST。
  - Solver：MJX-Warp 除 PGS/noslip 外全支持；MJX-JAX 为 CG/NEWTON。
  - Cone：两者均 pyramidal+elliptic；Condim：MJX-Warp 全支持，MJX-JAX 1/3/4/6（ELLIPTIC 下不支持 1）。
  - Fluid：MJX-Warp 全部；MJX-JAX 仅 `flInertia`。
  - Flex：MJX-Warp 支持 VERTCOLLIDE/ELASTICITY；**MJX-JAX 不支持**。
  - Jacobian：MJX-Warp DENSE+SPARSE；MJX-JAX 仅 DENSE。
  - Ray：MJX-Warp 全支持且 mesh/hfield/flex 有 BVH；MJX-JAX mesh/hfield/flex 慢或未实现。
  - Sensors：MJX-Warp 除 PLUGIN 外全部；MJX-JAX 为长列表子集（列出 30+ 种）。
  - 性能调优官方建议（MJX-JAX）：降低 `iterations`/`ls_iterations`、显式 `contact/pair` 减少候选接触、`maxhullvert` ≤64、视情况关 `eulerdamp`、`jacobian` 显式选 dense/sparse（TPU 用 sparse+Newton 可提速 2~3×，GPU 用 dense 约 10~20%）、broadphase 需手设 `max_contact_points`/`max_geom_pairs`；GPU 建议 `XLA_FLAGS=--xla_gpu_triton_gemm_any=true`（官方称 NVIDIA GPU 可 ~30% 提速）。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>
- **B 传感器**：沿用 MuJoCo sensor 体系（MJX-JAX 子集见上表）。**批量渲染提供 RGB/深度/分割**：`create_render_context` 参数含 `render_rgb`/`render_depth`/`cam_res`/`use_textures`/`use_shadows`/`enabled_geom_groups`；`mjx.render` 返回 `(rgb, depth, d)`，**`mjx.render_with_segmentation` 返回 `(rgb, depth, seg, d)`**（3.12.0 起把 `mjx.Data` 追加为返回值末项）。说明：`nworld` 在创建 render context 时固定，且已知 `render` 与 `jax.vmap(jax.lax.scan)` 配合有问题。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- **C 建模**：同 MuJoCo（MJCF/URDF/MJZ/OpenUSD）；`mjx.Model` 支持 **batch 维做领域随机化**；另注 `mjx.Model` 的 numpy 字段是「结构性字段」，改了会触发 JIT 重新编译（如 `jnt_limited`），而 JAX array 字段可运行时改（如 `jnt_range`）。
- **D 算法生态**：**MuJoCo Playground**（官方 Apache-2.0，含 dm_control 经典控制环境、四足/双足运动、非抓取与灵巧操作、视觉环境；支持 MJX-JAX 与 `--impl warp`），**Brax 依赖 `mujoco-mjx`**（Brax 旧 generalized pipeline 已停止维护，MJX-JAX 是其继任者，由 MuJoCo 与 Brax 核心贡献者共建）；与 JAX 生态（`jit`/`vmap`/`pmap`）原生融合；`mjx-testspeed` 与 `mjx-viewer`（用 MJX 物理步进，便于调试求解器参数）两个 CLI。
- **E 仿真能力**：批量并行靠 `vmap`/`pmap`（多设备）；`Data.where(done, reset_data)` 统一支持批量子集 reset（MJX-Warp 下尤其必要）；**确定性/可复现性**：MJX-JAX 本身为 XLA 编译，官方未给确定性声明（**未查证**）；Playground FAQ 明确 Ampere+ GPU 上 JAX 默认 TF32 会造成复现性问题，需 `JAX_DEFAULT_MATMUL_PRECISION=highest`。
- **F 界面与交互**：`mjx-viewer` CLI（把 MJX 物理加载进 simulate viewer）。**无独立 GUI 编辑器；中文界面未查证。**
- **G 可视化**：**批量光线投射渲染器**（RGB + 深度；分割见 `render_with_segmentation`），支持多相机、纹理、阴影、geom group 选择；官方明确该渲染器「serves a different purpose than MuJoCo's renderer」，是高吞吐低保真（与 MJWarp 批量渲染器同源）。
- **H 部署**：`pip install mujoco-mjx`（依赖 `mujoco` 与 `mujoco-warp`）；需要 `pip install mujoco-mjx[warp]` 才能用 Warp 实现。可选 extra：`warp`。**Apple Silicon 官方支持（MJX-JAX）**。headless 天然支持。多 GPU 用 `create_render_context(devices=[...])` + `jax.pmap`。
- **I 精度实时性**：**MJX-JAX 不适合单场景**——官方明确「Simulating a single scene, MJX-JAX can be **10x** slower than MuJoCo」，最佳场景是「数千到数万个并行场景」；大网格碰撞是弱点（SAT 无分支实现，凸网格建议 ≤200 顶点、凸-凸 <32 顶点）；大量接触的复杂场景因分支发散性能下降快于 MuJoCo（官方给了 1~10 个 humanoid 的四个架构对照图与单 humanoid 数值：MuJoCo Apple M3 Max 650K SPS、AMD 3995WX 1.8M、A100(batch 8192) 950K、TPU v5e-8(batch 16384) 2.7M）。MJX-Warp CUDA graph 模式有性能权衡表（WARP / WARP_STAGED / WARP_STAGED_EX）。
- **J 生态**：Playground（训练配方 + CLI）、Brax、dm_control notebook、tutorial notebook（含 RL 训练 humanoid/quadruped）、与 MuJoCo 主线同版本号同节奏发布（3.13.0 于 2026-09-09）。
- **这个软件独有 / 明显强于别人的 3 项**：
  1. **官方支持 Apple Silicon 的 GPU 批量仿真**（对我们最直接可用）；同时覆盖 NVIDIA/AMD GPU 与 TPU。
  2. **可微物理（MJX-JAX）**：官方定位为「roughly supports gradients」，可做基于梯度的轨迹优化 / 可微 RL。
  3. **与 JAX 生态无缝同构**：`vmap`/`pmap`/`jit`/`lax.scan` 直接组合，`mjx.Model` 的 batch 维天然表达领域随机化，批量渲染也在 `jit` 内（`rc.pytree()`）。
- **已知短板 2~3 项**：
  1. **单场景慢约 10×**，大网格碰撞与多接触复杂场景性能显著弱于 MuJoCo；部分 geom/solver/flex/fluid 特性缺失或受限（见 A 节表）。
  2. 批量渲染器低保真（无 GI / PBR），`nworld` 固定、与 `vmap(lax.scan)` 组合有已知问题；分割只在 `render_with_segmentation` 提供。
  3. 可微性为 "mostly supported" 而非完全；TF32 带来复现性坑（需手动设环境变量）。

## 软件名：Genesis（Genesis World 1.4.1，2026 年）
- **一句话定位**：把「统一多物理引擎（刚体/FEM/MPM/PBD/SPH/烟雾/IPC）+ 自研光追渲染器 Nyx + 跨平台编译器 Quadrants」放在一个 Pythonic API 后的物理 AI 仿真平台，从笔记本 CPU 一路扩到数据中心 GPU（[官方 Introduction](https://genesis-world.readthedocs.io/en/latest/user_guide/overview/what_is_genesis.html)、[PyPI 1.4.1](https://pypi.org/project/genesis-world/)）。
- **许可证 / 闭源商用**：Apache 2.0，允许闭源商用（[PyPI License 段](https://pypi.org/project/genesis-world/)）。注意 Nyx 渲染器是独立的 `gs-nyx` 包，当前「通过内部包索引分发，尚未上 PyPI」（[Nyx renderer 页](https://genesis-world.readthedocs.io/en/latest/user_guide/rendering/nyx_renderer.html)），其许可条款需单独核对：**未查证**。
- **支持平台（含 macOS）**：Linux / Windows / macOS；后端 CUDA、AMD ROCm、Apple Metal（`gs.metal`）、CPU。官方支持矩阵明确 macOS + Apple Silicon 的 **GPU 仿真 ✅ / CPU 仿真 ✅ / 交互查看器 ✅ / 无头渲染 ✅**。`gs.gpu` 解析顺序为 CUDA → AMD → Metal → CPU；Intel GPU 只能驱动查看器与离屏渲染，无仿真后端（[Installation](https://genesis-world.readthedocs.io/en/latest/user_guide/overview/installation.html)、[Initialization and backends](https://genesis-world.readthedocs.io/en/latest/user_guide/configuration/initialization.html)）。**对 Apple M5 macOS 是本报告五者中最正面的一个。**
- **A 物理引擎**：不基于 PhysX/Bullet/MuJoCo，而是自研统一多物理引擎，由 [Quadrants](https://github.com/Genesis-Embodied-AI/quadrants) 编译器（2025 年 6 月从 Taichi fork）下推到 CUDA / AMD ROCm / Apple Metal / Vulkan / x86 / ARM64。求解器族：Rigid、FEM、MPM、PBD、SPH、Stable Fluid（烟雾）、IPC（libuipc 后端）、以及 SAP 耦合器与显式耦合器，全部共享「一个场景、一个状态」（[Introduction](https://genesis-world.readthedocs.io/en/latest/user_guide/overview/what_is_genesis.html)、[Beyond rigid bodies](https://genesis-world.readthedocs.io/en/latest/user_guide/physics/beyond_rigid_bodies.html)）。刚体接触模型：软约束（soft constraint）公式，Jacobian + 参考加速度 + 刚度对角阵；摩擦锥可选**金字塔锥（默认）**或**椭圆锥**，接触求解可选 **`convex`（MuJoCo 公式）**或 **`signorini`（需椭圆锥 + Newton 求解器）**；支持扭转摩擦 `enable_torsional_friction` 与滚动摩擦 `enable_rolling_friction`；约束求解器可选 **Newton（默认，Cholesky，CPU 可用稀疏带状分解）**或 **CG（预条件共轭梯度）**；`iterations`/`tolerance`/`ls_iterations`/`ls_tolerance` 可调（[Constraint model](https://genesis-world.readthedocs.io/en/latest/user_guide/theory/rigid_solver/constraints.html)）。软体/可形变/流体：MPM（Elastic/Liquid/ElastoPlastic/Sand/Snow/Muscle）、FEM（Elastic/Cloth/Muscle，暴露杨氏模量 E 与泊松比 nu）、PBD（Cloth/Elastic/Liquid/Particle）、SPH（Liquid，参数 rho/mu/gamma）、Stable Fluid（烟雾，Eulerian 网格 + Jacobi 压力投影）（[Beyond rigid bodies](https://genesis-world.readthedocs.io/en/latest/user_guide/physics/beyond_rigid_bodies.html)）。GPU 并行规模：官方称单 GPU 支持「tens of thousands of environments」，`scene.build(n_envs=B)` 一次 `scene.step()` 推进整批（[Parallel simulation](https://genesis-world.readthedocs.io/en/latest/user_guide/getting_started/parallel_simulation.html)）；吞吐的官方量化声明为「相对 Isaac Gym/Sim/Lab 与 MuJoCo MJX 最高 10–80×，且不牺牲精度」（[Introduction](https://genesis-world.readthedocs.io/en/latest/user_guide/overview/what_is_genesis.html)，方法论在官方博客 [genesis.ai blog](https://www.genesis.ai/blog/the-role-of-simulation-in-scalable-robotics-genesis-world-10-and-the-path-forward)）。

- **I 精度与实时性**：物理步长 `SimOptions(dt=...)`（示例默认 dt=0.01 s），非刚性求解器需 `substeps`（内部子步 = dt/substeps，示例 4e-3 / 10 → 4e-4 s）；固定频率控制环通过每步 `control_dofs_*` + PD 增益实现；精度 `"32"`（默认）/`"64"`（Metal 不可用），整数索引恒为 32 位；`performance_mode=True` 把静态 shape 烘进 kernel，官方称约 **+30% 仿真速度**（代价是场景变化需重新编译，可能数分钟）；默认在终端打印实时仿真 FPS，可用 `ProfilingOptions(show_FPS=False)` 关闭；CPU 单线程性能与具体实时因子：**未查证**（官方提供 `examples/speed_benchmark` 与 [Profiling](https://genesis-world.readthedocs.io/en/latest/user_guide/developers/profiling.html) 页，但本报告未取得具体数值）。数值可复现/确定性：见 E（CPU 完整、GPU 部分；`QD_PERFDISPATCH_FORCE` 可手动钉死实现以复现）（[Initialization and backends](https://genesis-world.readthedocs.io/en/latest/user_guide/configuration/initialization.html)）。
- **J 生态与文档**：资产库：包内自带 `genesis/assets`（相对路径找不到时回落到该目录，例如 `xml/franka_emika_panda/panda.xml`、`urdf/go2/urdf/go2.urdf`）（[Loading assets](https://genesis-world.readthedocs.io/en/latest/user_guide/assets/loading_assets.html)）；另有 USD 导入与网格处理（凸分解/简化）专页。教程：Getting Started（Hello / Control / Parallel / More examples）、物理实体、机器人控制、传感器、渲染、资产、策略训练、理论建模、开发者文档，且**提供完整中文文档站点**（[zh-cn](https://genesis-world.readthedocs.io/zh-cn/latest/)）。插件机制：自定义传感器（Sensor pipeline + Writing a custom sensor）、viewer plugin、Nyx 相机插件、`genesis-world[render]` / `[dev]` / `[usd]` extras、`pyuipc`（IPC，Linux/Windows x86 + NVIDIA GPU）（[PyPI](https://pypi.org/project/genesis-world/)）。更新节奏：极快——1.0.0（2026-05-27）→ 1.4.1（2026-09-12），约 1.2 版本/月（[PyPI Release history](https://pypi.org/project/genesis-world/#history)）。
- **这个软件独有 / 明显强于别人的 3 项**：
  1. **一个场景内统一刚体/FEM/MPM/PBD/SPH/烟雾/IPC 多求解器并带显式 + SAP + IPC 耦合器**，还配可微仿真与自研编译器后端——其余四个都不具备这种「多物理 + 跨后端 + 可微」的组合（[Beyond rigid bodies](https://genesis-world.readthedocs.io/en/latest/user_guide/physics/beyond_rigid_bodies.html)、[Introduction](https://genesis-world.readthedocs.io/en/latest/user_guide/overview/what_is_genesis.html)）。

- **已知短板 2~3 项**：

  3. **macOS 上的能力天花板**：Metal 后端无 double 精度、GPU 确定性仅部分支持，Nyx 又需额外安装（且当时仍未上 PyPI）（[Initialization and backends](https://genesis-world.readthedocs.io/en/latest/user_guide/configuration/initialization.html)、[Nyx renderer](https://genesis-world.readthedocs.io/en/latest/user_guide/rendering/nyx_renderer.html)）。

- **A 物理引擎**：底层为 **SAPIEN + NVIDIA PhysX**，ManiSkill 的价值在于**把物理放到 GPU 上并行**：所有 actor/articulation 被塞进**同一个 PhysX scene**，每个任务占一小块 **sub-scene**；读到的位姿会自动相对 sub-scene 中心预处理；sub-scene 间距由 `sim_config.spacing` 决定，**间距过小会让不同子场景的物体互相碰撞（官方点名的常见 bug）**（[GPU Simulation](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/gpu_simulation.html)）。GPU 生命周期：`env.reset` 依次做重配置加载 → `physx_system.gpu_init()` → 初始化 actor → `gpu_apply_*` → `gpu_update_articulation_kinematics()` → `gpu_fetch_*`；`env.step` 则 action 处理 → `gpu_apply_articulation_target_position/velocity` → `physx_system.step()` → `gpu_fetch_*`（[GPU Simulation](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/gpu_simulation.html)）。**GPU 并行官方数字：高端配置下在 4090 上以 30,000+ FPS 采集 RGBD + Segmentation 数据**（[文档首页](https://maniskill.readthedocs.io/en/latest/)、[PyPI](https://pypi.org/project/mani-skill/)）。**异构并行**：每个并行环境可以有完全不同的场景/物体集合（[文档首页](https://maniskill.readthedocs.io/en/latest/)）。软体/可形变/流体：**不支持 / 未查证到**（体系为刚体 + 铰接；`Actor.merge` / `Articulation.merge` 只是 GPU 缓冲视图重组）。接触模型：继承 PhysX（见 SAPIEN 条）；求解器精度选项：**未查证**。
- **B 传感器**：官方明确「**At the moment there is only the Camera sensor type**」——即**只有相机一种传感器**，没有 LiDAR / IMU / 力触觉（[Sensors / Cameras](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html)）。相机可选 **shader pack**：`minimal`（最快、背景恒黑）、`default`（速度/可用纹理平衡）、`rt` / `rt-med` / `rt-fast`（光追，质量递减速度递增）；可用**纹理**：`rgb [H,W,3] uint8`、`depth [H,W,1] int16 毫米`、`position [H,W,4] int16 毫米 + 分割通道`、`segmentation [H,W,1] int16 唯一 ID`、`normal [H,W,3] float32`、`albedo [H,W,3] uint8`（[Sensors / Cameras](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html)）。三类相机：sensor（供策略观测）、human_render_camera（高质量视频）、viewer camera（GUI）；支持按组或按相机名覆盖参数，例如 `human_render_camera_configs=dict(shader_pack="rt")`（[Sensors / Cameras](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html)）。**传感器噪声/真实感建模：未查证**（官方未提供噪声 API 文档）。光追：通过 `rt` 系列 shader 实现照片级渲染（[Sensors / Cameras](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html)）。
- **C 建模**：机器人/物体加载走 SAPIEN 体系（URDF loader 在 SAPIEN 侧有官方文档）；ManiSkill 提供 [Loading Actors and Articulations](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/custom_tasks/loading_objects.html) 与 [Custom Robots](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/custom_robots.html) 教程。**MJCF / USD / STEP / IGES 支持：未查证**（本报告未逐页核对 Loading Objects 全文）。关节驱动：可对每个关节 `set_drive_properties(stiffness, damping, force_limit)` 与 `set_friction(friction)`，并在 `_load_scene` 与 `_initialize_episode` 两个时机做随机化（[Domain Randomization](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/domain_randomization.html)）。摩擦与减速器建模：碰撞形状级 `physical_material.dynamic_friction / static_friction / restitution` 可逐环境设置；**减速器/reducer 建模：未查证**。软体建模：不支持。
- **D 算法生态**：ROS/ROS2 bridge：**未查证**。MoveIt：**不集成**——操作数据采集走官方 **mplib**（随 ManiSkill 一起安装），文档给出 Panda 的 motion planning 示例（`python -m mani_skill.examples.motionplanning.panda.run -e "PickCube-v1"`），并直言 motion planning 的局限是「需要人工调参编写、且无法生成更动态任务的解」（[Motion Planning](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/motionplanning.html)）。RL：`gym.make("PickCube-v1", num_envs=N)` 直接给**批量**环境（非标准 Gymnasium API），可加 `CPUGymWrapper` 得到标准单环境 API，或加 `ManiSkillVectorEnv` 得到 Gymnasium `VectorEnv` API（返回的是 GPU 上的 torch 张量而非 numpy）；内置基线 **PPO、SAC、TD-MPC2**；评测规范要求 `reconfiguration_freq=1` + `ignore_terminations=True` + `record_metrics=True`，记录 `success_once` / `success_at_end` / `fail_once` / `fail_at_end` / `return`（[RL Setup](https://maniskill.readthedocs.io/en/latest/user_guide/reinforcement_learning/setup.html)、[文档首页](https://maniskill.readthedocs.io/en/latest/)）。模仿学习：**Behavior Cloning、Diffusion Policy**；VLA：**Octo、RDT-1B、RT-x**；另有 **sim2real 示例**与 **Real2sim 环境**（"scalably evaluating real-world policies 100x faster via GPU simulation"）（[文档首页](https://maniskill.readthedocs.io/en/latest/)、[Sim2Real Tools](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/sim2real/index.html)）。系统辨识 sysid：**未查证**（有 sim2real/real2sim 工具链，但未见专门 sysid 模块）。
- **E 仿真能力**：大规模并行见 A；域随机化覆盖面很广：**相机**（位姿/内参/fov/near/far，重配置期直接给批量数据；重置期可通过 kinematic mount 改相机位姿）、**Actor/Link 物理与视觉材质**（需逐环境分开 build 再 `Actor.merge`，否则因共享材质优化而全环境相同）、**机器人/控制器**（关节 stiffness/damping/force_limit/friction，`build_separate=True`）、**光照/渲染**（ambient light、directional light、shadow_map_size）、**背景/分割**（改贴图，或按 `per_scene_id` 做绿幕替换，ID 0 保留给背景）、**外力扰动**（`actor.apply_force`，目前仅 Actor 支持）（[Domain Randomization](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/domain_randomization.html)）。时间回溯/重放：有 [Replaying/Converting Trajectories](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/replay.html)、`RecordEpisode` wrapper（视频 + 轨迹）、motion planning 示例默认把轨迹存成 **`.h5`**（存到 `demos/motionplanning/<env_id>`）（[Motion Planning](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/motionplanning.html)、[Wrappers](https://maniskill.readthedocs.io/en/latest/user_guide/wrappers/index.html)）。演示数据集与 [Datasets](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/index.html) 章。可复现性：`_batched_episode_rng`（`BatchedRNG`，等价于带 batch 维的 `np.random.RandomState`）；`env.reset(seed=x)` 时若 x 为整数则第一个并行环境用 x、其余由 x 派生，`env.reset(seed=[x1,…,xn])` 可完全确定；轨迹可复现的另一条路是保存/恢复 **environment state**（关节角/速度/位姿/速度，不含贴图、固定相机位姿、控制器刚度等）（[Reproducibility and RNG](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/rng.html)）。
- **F 界面与交互**：GUI 基于 SAPIEN viewer（demo 脚本支持 `--vis` 开 GUI、`--render-mode="human"`），macOS 页给出「Control Tab → Pause」等操作建议（[MacOS Installation](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/macos_install.html)、[Motion Planning](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/motionplanning.html)）；有 **遥操作** 数据采集（[Teleoperation](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/teleoperation.html)）。脚本语言：Python（配置用 Gym `make` kwargs + 面向对象 task 类）。图形化模型编辑器：**无 / 未查证**。拖拽交互：**未查证**。**中文界面支持：无 / 未查证**（文档仅英文，另有中文社区项目列在 [Community Projects](https://maniskill.readthedocs.io/en/latest/user_guide/additional_resources/community_projects.html)，但未核对内容）。
- **G 可视化**：**光追渲染是 ManiSkill 的卖点之一**——`rt` / `rt-med` / `rt-fast` 三档光追 shader（质量与速度递减），用于照片级渲染；文档首页 teaser 即为「ray-tracing 渲染的环境/机器人样例，场景数据来自 AI2THOR 与 ReplicaCAD」（[Sensors / Cameras](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html)、[文档首页](https://maniskill.readthedocs.io/en/latest/)）。深度/分割导出：通过 `depth` / `position` / `segmentation` 纹理直接从 `env.reset()` / `env.step()` 的观测里取（不是 `env.render()`——官方专门把「用 `env.render(mode="rgb_array")` 拿图像观测」列为**常见错误**）（[RL Setup — Common Mistakes](https://maniskill.readthedocs.io/en/latest/user_guide/reinforcement_learning/setup.html)）。视频导出：`RecordEpisode` wrapper（[Wrappers](https://maniskill.readthedocs.io/en/latest/user_guide/wrappers/index.html)）。多视口：**未查证**（多相机支持明确）。多环境渲染：shader 与 GPU 缓冲区支持并行多 sub-scene 渲染（[GPU Simulation](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/gpu_simulation.html)）。
- **H 部署**：安装：`pip install --upgrade mani_skill torch`，或每日更新的 `mani_skill-nightly`；另提供 Docker Hub `maniskill/base`（[Installation](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html)、[Docker](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/docker.html)）。资产默认存 `~/.maniskill/data`，可用 `MS_ASSET_DIR` 改，`MS_SKIP_ASSET_DOWNLOAD_PROMPT=1` 跳过下载提示（[Installation](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html)）。**macOS/Apple M5 见上：可 CPU 仿真 + 渲染（需 Vulkan/MoltenVK），无 GPU 仿真；官方建议重负载放到 CUDA 机器（如 Colab）**（[MacOS Installation](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/macos_install.html)）。无头：支持（`--save-video` 可 headless 只出视频）（[Motion Planning](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/motionplanning.html)）。云/远程：官方 Colab 快速上手（"Everything is runnable on Colab free tier"）+ Docker（[PyPI](https://pypi.org/project/mani-skill/)）。许可：环境 Apache-2.0 / 资产 CC BY-NC 4.0（非商用）——**闭源商用需替换资产**（[PyPI License](https://pypi.org/project/mani-skill/)）。
- **I 精度与实时性**：控制频率/动作空间由 `Controllers` 抽象管理（[Controllers / Action Spaces](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/controllers.html)）；物理步长可在 sim_config 中配置（**具体默认值未查证**）；官方有专门的 [Performance Benchmarking](https://maniskill.readthedocs.io/en/latest/user_guide/additional_resources/performance_benchmarking.html) 页（本报告未核对其中数值）；**实时因子、CPU 单线程性能：未查证**。数值可复现/确定性：见 E（BatchedRNG + env state 双轨，官方明确讨论「跨机器重放演示数据」的困难）（[Reproducibility and RNG](https://maniskill.readthedocs.io/en/latest/user_guide/concepts/rng.html)）。
- **J 生态与文档**：资产/场景：AI2THOR、ReplicaCAD 场景数据集，[Scene Datasets](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/scenes.html) 与 [Demonstrations](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/demos.html)；任务覆盖 humanoid、mobile manipulator、单臂机器人，以及桌面/绘画清洁/灵巧操作等（[文档首页](https://maniskill.readthedocs.io/en/latest/)）。教程：Getting started（Installation / Quickstart / Docker）、Demos、Tutorials（自定义任务/机器人/可复用场景/域随机化/sim2real）、Concepts、Datasets、Data Collection、RL、Learning from Demos、VLA、Wrappers + Colab notebook（[文档导航](https://maniskill.readthedocs.io/en/latest/user_guide/index.html)）。插件机制：面向对象的 task building API（继承 `BaseEnv`，覆写 `_load_scene` / `_load_agent` / `_load_lighting` / `_initialize_episode` / `_default_sensor_configs`），Python 原生扩展（[Domain Randomization](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/domain_randomization.html)）。更新节奏：3.0.1 发布于 2026-04-21，并有**每日 nightly**（`mani_skill-nightly`）（[PyPI](https://pypi.org/project/mani-skill/)、[Installation](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html)）。
- **这个软件独有 / 明显强于别人的 3 项**：
  1. **GPU 并行视觉数据采集吞吐**：官方数字为 4090 上 **30,000+ FPS 的 RGBD + Segmentation**（[文档首页](https://maniskill.readthedocs.io/en/latest/)）——这是五者中唯一给出可比的「视觉数据采集 FPS」指标。

- **支持平台（含 macOS）**：**这是本报告中对 macOS 最不利的一个**。官方仓库存在标题为 **"Only Linux 64 support" 的 issue #2358**，表明 habitat-sim 实际只支持 Linux 64 位（[issues/2358](https://github.com/facebookresearch/habitat-sim/issues/2358)）；PyPI 上 habitat-lab 的 classifier 列了 MacOS 与 Unix，且 habitat-lab 文档称 `examples/interactive_play.py` 可「在 Linux 或 MacOS 上运行」（[PyPI habitat-lab](https://pypi.org/project/habitat-lab/)、[Habitat 2.0 Overview](https://aihabitat.org/docs/habitat-lab/habitat2.html)）——但 habitat-lab 只是高层库，**核心仿真器 habitat-sim 不支持 macOS**，所以 **Apple M5 上无法获得可用的完整 Habitat 栈**。macOS 上能跑的部分：**未查证**（推测仅 habitat-lab 的 Python 侧逻辑）。Windows 支持：**未查证**（未见于官方表述）。
- **A 物理引擎**：habitat-sim 内置物理模拟，官方仓库有 **"Bullet Physics Integration"（PR #91）** 与 **"RenderCamera::unproject and Simulator::castRay via Bullet physics"（commit）**，可据此确认物理/射线投射走 **Bullet**（GitHub 搜索结果标题，**本报告未能直接抓取仓库正文，按「搜索结果级证据」标注**：[PR #91](https://github.com/facebookresearch/habitat-sim/pull/91)、[commit cdc29b4](https://github.com/facebookresearch/habitat-sim/commit/cdc29b4a3238bd5cbb7b0d1727373abe46ea8f36)）。可用接口：`Simulator.step_physics(1.0/60.0)`、`sim.get_world_time()`、`sim.get_gravity()`；物体分 **MotionType.DYNAMIC / KINEMATIC / STATIC**；提供 `VelocityControl`（可全局或局部坐标系、可控制线/角速度，对 KINEMATIC 物体直接改状态、对 DYNAMIC 物体每步设初速度），以及 `apply_force()` / `apply_torque()`（**力/力矩在每次 `step_physics()` 调用内视为常量，调用后清空**）（[Interactive Rigid Objects](https://aihabitat.org/docs/habitat-sim/managed-rigid-object-tutorial.html)）。还有与 NavMesh 结合的连续控制（`sim.step_filter`，可配置 `allow_sliding`）（同上）。软体/可形变/流体：**未见通用软体/流体求解器（未查证到）**；但 Habitat 3.0 明确「models complex deformable humanoid bodies」（人形为可形变体）（[Habitat 3.0 官网](https://aihabitat.org/habitat3/)）。**GPU 并行物理仿真：未查证到**（官方只声明渲染侧的多进程 GPU 吞吐，见下）。接触模型与求解器精度选项：**未查证**。
- **B 传感器**：官方 `CameraSensorSpec` 支持传感器类型 **COLOR（RGBA）/ DEPTH / SEMANTIC**，并可指定 `sensor_subtype`（如 `PINHOLE`）与 `resolution`、`position`、`orientation`；**同一 agent 的所有 sensor 必须同分辨率**；**支持立体相机对**（两个 uuid 不同的相机，RGB 或 depth 均可）（[Stereo agent](https://aihabitat.org/docs/habitat-sim/stereo-agent.html)、[Interactive Rigid Objects](https://aihabitat.org/docs/habitat-sim/managed-rigid-object-tutorial.html)）。habitat-lab 的 Demo 同时可视化 **rgb / semantic / depth** 三通道，并可通过 `HabitatSimSemanticSensorConfig` 配置语义传感器分辨率；场景语义标注可按 Level → Region → Object 层级遍历（id / category / aabb）（[Habitat Lab Demo](https://aihabitat.org/docs/habitat-lab/habitat-lab-demo)）。**LiDAR / IMU / 力触觉传感器：未查证**（官方教程中未见）。传感器噪声/真实感建模：**未查证**（官方有 `test_pyrobot_noisy_controls.py` 之类测试，但**本报告未核对其内容**）。**光追：未查证到**（渲染为光栅路径，见 G）。音频：从 `stereo_agent.py` 中的注释可见编译期有 audio 选项（"when audio is enabled in sim compilation"），但细节**未查证**（[Stereo agent](https://aihabitat.org/docs/habitat-sim/stereo-agent.html)）。
- **C 建模**：对象/场景资产以 **`.glb` + `.object_config.json`** 形式加载（`ObjectAttributes`，含 `render_asset`、`force_flat_shading` 等），场景 ID 形如 `data/scene_datasets/.../apartment_1.glb`；有 `ObjectAttributes` / `AssetAttributes` 模板管理器与 `RigidObjectManager`（[Interactive Rigid Objects](https://aihabitat.org/docs/habitat-sim/managed-rigid-object-tutorial.html)、[Working with Lights](https://aihabitat.org/docs/habitat-sim/lighting-setups.html)）。**关节物体（articulated objects）**：官方 Resource Index 把 "Articulated Object API" 列为 **TODO（文档待补）**，即能力存在但文档未完成（**细节未查证**）（[Resource Index](https://aihabitat.org/docs/resource_index/)）。**URDF / MJCF / USD 支持：未查证**。**CAD STEP/IGES 导入：未查证**。关节驱动/执行器模型、摩擦与减速器建模：**未查证**（物理接口层面只有 VelocityControl 与 force/torque）。软体建模：未见通用软体；人形为可形变体（[Habitat 3.0 官网](https://aihabitat.org/habitat3/)）。
- **D 算法生态**：ROS/ROS2 bridge：**未查证**。MoveIt / 运动规划：**未查证**（无相关模块；导航用 NavMesh 而非运动规划库）。RL：**habitat-baselines 提供 DD-PPO**（`python -u -m habitat_baselines.run --config-name=rearrange/rl_skill.yaml`），以及 **TP-SRL**（task-planning with skills，用 PDDL 组合低层技能策略）基线；技能包括 pick、place、nav_to_obj、open/close_cab、open/close_fridge（[Habitat 2.0 Overview](https://aihabitat.org/docs/habitat-lab/habitat2.html)）。另有 **Gym API 教程 notebook**（`habitat2_gym_tutorial.ipynb`），说明有 Gym 风格接口（[Habitat 2.0 Overview](https://aihabitat.org/docs/habitat-lab/habitat2.html)）——**具体 API 细节未查证**。模仿学习：**未查证**（官方称训练方式涵盖 imitation / RL / 无学习，见 Quickstart 对 habitat-lab 的描述，但**本报告未核实具体 IL 管线**）（[Quickstart](https://aihabitat.org/docs/habitat-lab/quickstart.html)）。系统辨识 sysid：**未查证**。
- **E 仿真能力**：吞吐声明（渲染侧）：**渲染 Matterport3D 场景时单线程数千 FPS，单 GPU 上多进程超过 10,000 FPS**（[Habitat Sim Docs](https://aihabitat.org/docs/habitat-sim/)）。大规模并行（物理）：**未查证到 GPU 并行物理**。域随机化：官方 Lighting 教程明确把「自定义场景光照 setup」列为适用于 "domain randomization" 的场景，且光照 setup 可动态修改、可命名注册多套、可按对象指定（但**切换 Flat 与 PBR/Phong 着色必须关闭并重新初始化 Simulator**）（[Working with Lights](https://aihabitat.org/docs/habitat-sim/lighting-setups.html)）。时间回溯/重放：**Gfx Replay**（录制与回放仿真），官方有 `replay_tutorial.ipynb`（[Resource Index](https://aihabitat.org/docs/resource_index/)）；另有 **ImageExtractor** 工具可离线批量产出合成图像数据集（[Resource Index](https://aihabitat.org/docs/resource_index/)）。录制与数据导出格式：`viz_utils.make_video` 输出视频（示例里用 fps=60、depth_clip 等参数）、`make_video` 支持多路 overlay（[Interactive Rigid Objects](https://aihabitat.org/docs/habitat-sim/managed-rigid-object-tutorial.html)）；**Gfx Replay 的具体文件格式：未查证**。可复现性（固定随机种子）：**未查证**。
- **F 界面与交互**：**无内置图形化模型编辑器**（官方未提供）。交互方式：`examples/interactive_play.py --never-end` 用键盘鼠标控制机器人（需 PyGame，可在 Linux 或 MacOS 运行）（[Habitat 2.0 Overview](https://aihabitat.org/docs/habitat-lab/habitat2.html)）；**Habitat 3.0 提供 human-in-the-loop 界面，人可用鼠标键盘或 VR 与自主机器人协作**（[Habitat 3.0 官网](https://aihabitat.org/habitat3/)）；Quickstart 用 OpenCV 窗口显示 RGB 并读键盘（[Quickstart](https://aihabitat.org/docs/habitat-lab/quickstart.html)）；**Asset Viewer** 可交互查看 3D 资产（[Resource Index](https://aihabitat.org/docs/resource_index/)）。脚本语言：Python（配置体系为结构化 config + `read_write` 覆盖；本报告未核对是否用 Hydra/OmegaConf：**未查证**）。拖拽交互：**未查证**。**中文界面支持：无 / 未查证**（官方文档全英文）。
- **G 可视化**：渲染路径为 **光栅化**（Magnum 图形栈，`mn` 模块贯穿教程），提供 **Flat / Phong / PBR** 三种着色（其中 PBR 与 Flat 之间切换必须重启 Simulator）；预定义光照 setup：`NO_LIGHT_KEY`（0 盏灯，适合烘焙贴图的扫描场景如 MP3D）与 `DEFAULT_LIGHTING_KEY`（2 盏白色全局光）；可自定义/注册/按对象指定多套 light setup，支持 `LightPositionModel.Global` 与 `.Camera`（[Working with Lights](https://aihabitat.org/docs/habitat-sim/lighting-setups.html)）。**阴影与反射：未查证**（官方光照教程未展开阴影/反射）。**路径追踪/光追渲染器：未查证到**（对比 Genesis/SAPIEN/ManiSkill 的 RT 能力，这是 Habitat 的相对弱项）。深度/分割导出：传感器原生输出 DEPTH 与 SEMANTIC，Demo 中直接可视化；视频导出用 `viz_utils.make_video`（含 depth_clip 与多路 overlay）；有 ImageExtractor 离线导出图像数据集（[Habitat Lab Demo](https://aihabitat.org/docs/habitat-lab/habitat-lab-demo)、[Resource Index](https://aihabitat.org/docs/resource_index/)）。多视口：**未查证**；**立体相机对**已确认支持（[Stereo agent](https://aihabitat.org/docs/habitat-sim/stereo-agent.html)）。

- **这个软件独有 / 明显强于别人的 3 项**：

## MuJoCo Studio 的官方定位（专节）

**① 官方唯一的公开表述（MuJoCo 官方文档 Visualization 章节开头的 note 框，原文照录）：**

> **MuJoCo Studio**
> We are actively developing a new visualizer platform called [MuJoCo Studio](.../src/experimental/studio). We will update this section once it becomes more established.

来源：<https://mujoco.readthedocs.io/en/stable/_sources/programming/visualization.rst.txt>

**② 结论：它是「官方实验性、未定稿的下一代可视化平台」，而不是正式发布的稳定产品。**
- 位置：`src/experimental/studio/`（"experimental" 是仓库既有的实验目录，同目录还有同样被标为实验的其他组件，例如 OpenUSD 解析直到 3.5.0 才「moved out of experimental into a mjpDecoder plugin」）。
- 官方并未使用「API 不稳定」这类字眼，而是用「actively developing」+「once it becomes more established」+ note 框的形式，明确表示**尚不推荐/不承诺**。因此准确表述是：**官方未承诺 API 或行为稳定性；文档明确「等它更成熟后再更新本节」。**
- **无公开功能列表文档**：readthedocs 导航（Overview / Computation / Modeling / XML Reference / Programming / API Reference / Python / MJX / MJWarp / Unity / OpenUSD / Models / Changelog）中**没有 Studio 页**；Python 文档列的模块只有 `mujoco.rollout` 与 `mujoco.minimize`（**没有** `mujoco.experimental.studio`，也没有 `mujoco.sysid`，说明这两个都还没进正式 API 文档）。官方 changelog 里 Studio 只在 3.12.0 条目中以「simulate 与 MuJoCo Studio 的 control slider 现在按 control 生成并按 actuator 名 + input 名标注」被顺带提及——即它已在随版本演进，但未作为独立特性宣布。
  来源：<https://mujoco.readthedocs.io/en/stable/_sources/python.rst.txt>（Modules 段）、<https://mujoco.readthedocs.io/en/stable/_sources/index.rst.txt>（toctree）、<https://mujoco.readthedocs.io/en/stable/_sources/changelog.rst.txt>
- 本清单无法从官方渠道取得 Studio 的启动方式（是否为独立可执行文件 / 是否 `python -m` / 是否随 pip 分发）→ **「如何启动 Studio」标为未查证。** 关于用户提问中提到的 `mujoco.experimental.studio` 这一 Python 路径：官方文档与 PyPI 页面均未列出该模块，**未查证其存在**；本清单中 Studio 的能力描述全部来自官方仓库源码文件 `src/experimental/studio/app.h`（可直接访问的官方源文件）。

**③ 官方它是给谁用的？**
官方没有写 target audience。可信的推断依据只有两点：它被放在 `experimental/`，且被描述为「a new **visualizer platform**」（可视化平台，而非仿真引擎或 RL 框架）；从源码能力（Spec Explorer/Editor、ImGui 面板、Profiler、时间线、PiP）看，其目标用户是**需要交互式查看/编辑 MuJoCo 模型并调试仿真的研究人员与工程师**。**「目标用户」的官方明示：未查证。**

**④ 对「我们自研软件」的可行动结论：**
- Studio 目前**不可作为对标基线中的「成熟竞品」**，也不建议把产品路线押在复刻它上——它没有稳定 API 承诺、没有文档、没有平台矩阵。
- 但它泄露了官方未来方向：**图形化 spec 编辑 + Filament PBR + ImGui 面板 + 时间线回放 + profiler**。如果自研软件要在 macOS 上做出差异化，这几项恰是 MuJoCo 主线（simulate/viewer）目前缺失的，可作为「自研相对官方主线的领先点」写进报告。
- 更稳妥的对标基线应选：**MuJoCo `simulate`/`mujoco.viewer`（稳定、跨平台、macOS 官方支持）+ MJX（Apple Silicon GPU 批量）+ Studio（仅作趋势参考）**。

## 这类软件的共同点（5 条，基于本次全部 11 个软件的官方来源）

1. **物理引擎与渲染/前端解耦，「仿真本体」都以库 + Python 绑定交付。** MuJoCo 是 C 库 + pybind11（`pip install mujoco` 即含引擎本体），MJX/MJWarp 是同一 `mjModel`/`mjData` 的 GPU 重实现；Genesis 是 Quadrants 编译的 Python 引擎 + Nyx/Luisa/Pyrender 三条可换渲染路径；Isaac Lab 3.0 起把物理后端、渲染器、可视化器三层都做成可插拔；SAPIEN/ManiSkill 也是 C++ 核心 + pybind + Python 框架。**含义**：自研软件若把引擎与 GUI 强耦合，会在集成/自动化/CI/无头部署上全面落后。
   来源：<https://mujoco.readthedocs.io/en/stable/_sources/programming/index.rst.txt>、<https://genesis-world.readthedocs.io/en/latest/user_guide/overview/what_is_genesis.html>、<https://isaac-sim.github.io/IsaacLab/develop/source/refs/release_notes.html>

2. **「CPU 低延迟」与「GPU 高吞吐」是两条互斥路线，且各家都公开承认取舍——不在同一维度上比"谁最快"。** MuJoCo 官方：MJWarp 优化总步/秒、MuJoCo 优化单步延迟，「同一步 MJWarp 预期比 MuJoCo 慢」，MJX-JAX 单场景可慢 10×；Isaac Lab 官方：`--num_envs` 增大不一定更快（「more environments do not always make training faster」）；Genesis 的 10–80× 声明是"吞吐"而非"延迟"。**含义**：对标报告必须分「实时闭环（MPC/遥操作）」与「RL 采样/数据生成」两个场景分别列指标，否则结论没有意义。
   来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/mjx.rst.txt>、<https://isaac-sim.github.io/IsaacLab/develop/source/concepts/reinforcement_learning.html>

3. **GPU 并行 = 牺牲数值可复现性；"确定性"必须做成显式开关并标价。** MJWarp 官方 FAQ 直接回答「Is MJWarp on GPU deterministic? **No**」，确定性方案是退回 CPU；MuJoCo Playground 官方提示 Ampere+ GPU 上 JAX 默认 TF32 会破坏复现性，需 `JAX_DEFAULT_MATMUL_PRECISION=highest`；Isaac Lab 把确定性做成分档契约（`run_to_run` / `gpu_to_gpu`）并明确代价（内存与时延上升、MJWarp 下三个传感器不可用）；Isaac Lab 还明确警告"运行时域随机化物理材质"会破坏确定性，必须在 setup 阶段做；Genesis 用 `use_deterministic_algorithms=True` 换同机逐位复现。**含义**：自研软件若宣称"大规模并行 + 完全可复现"，要么限定 CPU/单线程，要么像这几家一样把确定性模式做成显式开关、写清代价与不适用场景。
   来源：<https://mujoco.readthedocs.io/en/stable/_sources/mjwarp/index.rst.txt>、<https://pypi.org/project/playground/>、<https://isaac-sim.github.io/IsaacLab/develop/source/features/reproducibility.html>、<https://genesis-world.readthedocs.io/en/latest/user_guide/configuration/initialization.html>

4. **感知传感器（相机/深度/分割/LiDAR）与物理传感器（IMU/力/触觉）在架构上分开，且"噪声与真实感"普遍是薄弱或需自建的一环——这正是一个可差异化的空档。** MuJoCo 明确把 RGB/深度相机排除在标准 sensor 模型之外（需程序化 offscreen 渲染），`sensor/noise` 官方定义"不影响仿真"；Isaac Lab 传感器齐全（Camera/RayCaster/Contact/IMU/PVA/JointWrench）但噪声模型未见官方文档；ManiSkill 官方直言「At the moment there is only the Camera sensor type」；Brax 完全没有传感器与渲染；SAPIEN 无 LiDAR/IMU/力触觉。**唯一把"传感器不完美"做成引擎级一等特性的是 Genesis**（IMU 的 noise/bias/random walk/轴间耦合/分辨率 + 全局 `delay`/`jitter` + 统一的 `read()` vs `read_ground_truth()`），MuJoCo 则在**延迟与采样周期**上做了引擎级支持（3.5.0 起 actuator/sensor 任意 delay + interval + zoh/linear/cubic 插值）。**含义**：把「传感器噪声 + 延迟 + 采样率 + 量化 + 标定内参 + 可复现」做成引擎级、可配置、默认可复现的一等特性，是官方产品普遍留白的位置。
   来源：<https://mujoco.readthedocs.io/en/stable/_sources/overview.rst.txt>、<https://mujoco.readthedocs.io/en/stable/_sources/modeling.rst.txt>、<https://genesis-world.readthedocs.io/en/latest/user_guide/sensing/imu.html>、<https://maniskill.readthedocs.io/en/latest/user_guide/concepts/sensors.html>

5. **主流引擎普遍采用宽松开源许可（Apache-2.0 / BSD-3 / MIT）作为生态护城河，商业价值上移到"平台与云"，但资产许可往往是隐藏红线。** MuJoCo 全家 + Playground + mjlab + Genesis + Isaac Sim + Brax + SAPIEN 均为 Apache-2.0 / BSD-3 / MIT；Isaac Lab 为 BSD-3（`isaaclab_mimic` 为 Apache-2.0）；**唯一例外是 ManiSkill：代码宽松但资产为 CC BY-NC 4.0（非商用）**。**含义**：自研软件若走闭源商用，竞争点不再可能是"许可"，而必须是官方普遍留白的维度——**中文界面/本地化、CAD（STEP/IGES)直接导入、图形化模型结构编辑器、传感器噪声与延迟的真实感、macOS 原生体验、以及"确定性 + 高性能"的工程化契约**。这五项在全部 11 个软件的官方文档中都属缺失或"未查证"，是清晰的可攻击面。
   来源：<https://pypi.org/project/mujoco/>、<https://pypi.org/project/genesis-world/>、<https://isaac-sim.github.io/IsaacLab/develop/source/refs/license.html>、<https://pypi.org/project/mani-skill/>、<https://pypi.org/project/sapien/>

**给"我们（M5 + macOS 自研软件）"的三条可行动结论：**

1. **唯一能在 M5 上跑「完整 GPU 并行 + GUI + 无头渲染 + 中文文档」的成熟对照组是 Genesis World。** 它也是唯一官方矩阵明确把 Apple Silicon GPU 列为 ✅ 的产品。对标时建议把 Genesis 当"能力上限基准"，把 MuJoCo 当"稳定/工程化基准"。
